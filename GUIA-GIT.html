Cómo clonar el proyecto, trabajar en tu rama y mergear a master. Escrita para quien nunca usó Git.

Actualizar master→ Crear rama→ Commitear→ Subir rama→ Pull request→ Merge

Preparación solo una vez

Esto se hace la primera vez y nunca más.

1 Instalar Git

Descárgalo de git-scm.com/downloads e instálalo dejando todas las opciones por defecto.

2 Presentarte ante Git

Abre PowerShell y dile a Git quién eres. Este nombre y correo aparecerán en cada commit que hagas.

git config --global user.name "Tu Nombre"
git config --global user.email "tucorreo@ejemplo.com"

3 Traer el proyecto

git clone https://github.com/Rafitipiti/hackacoes-grupo-3.git
cd hackacoes-grupo-3

clone descarga todo el proyecto y su historial completo.

Tu día a día cada vez que trabajes

Estos cinco pasos se repiten en cada tarea que tomes.

1 Actualizar tu copia de master

git checkout master
git pull
Hazlo siempre antes de empezar. Trabajar sobre una copia vieja es la causa número uno de conflictos.

2 Crear tu rama

git checkout -b nombre-de-tu-tarea

Una rama es tu espacio de trabajo aislado: lo que hagas ahí no toca master hasta que tú lo decidas.

Usa nombres descriptivos: filtro-por-empresa, grafico-evolucion, endpoint-trazabilidad.

3 Guardar tu avance (commitear)

Cada vez que termines algo que funcione:

git add .
git commit -m "Agregar filtro por empresa en el listado"

git add . marca todos tus cambios. git commit los guarda como un punto en la historia.

Commitea seguido y en pedazos chicos. Es mucho más fácil deshacer un cambio pequeño que uno gigante.

4 Subir tu rama

git push -u origin nombre-de-tu-tarea

Solo la primera vez lleva -u origin nombre-de-tu-tarea. De ahí en adelante basta con git push.

5 Integrar a master

Antes de integrar, trae lo último de master a tu rama para resolver los choques en tu espacio y no en el de todos:

git pull origin master

Si no hay conflictos, entra a GitHub: aparecerá el botón “Compare & pull request”. Ábrelo, describe qué hiciste y usa “Merge pull request”.

Para el hackatón pueden mergear directo. Si quieren más control, que otro integrante revise el pull request antes de aprobarlo.

6 Volver a empezar

git checkout master
git pull
git checkout -b siguiente-tarea

Comandos de rescate

Cuando algo se ve raro, empieza siempre por git status.

SituaciónComando
¿En qué rama estoy? ¿Qué cambié?git status
Ver el historialgit log --oneline
Descartar cambios de un archivogit checkout -- archivo.py
Deshacer el último commit, conservando los cambiosgit reset --soft HEAD~1
Ver todas las ramas que existengit branch -a
Cambiarte a una rama que ya existegit checkout nombre-rama

Cuatro reglas para no pisarse

  1. Nunca trabajen directo en master. Siempre una rama propia.
  2. git pull antes de empezar, siempre, sin excepción.
  3. Una rama por tarea. No acumulen tres funcionalidades distintas en la misma rama.
  4. Si aparece un conflicto, no lo resuelvan solos la primera vez. Git marca las zonas en choque con <<<<<<< y >>>>>>>; hay que elegir qué versión queda y borrar esas marcas. Háganlo entre dos la primera vez.
